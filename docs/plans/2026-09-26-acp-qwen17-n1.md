# ACP 指令版 8B 到 1.7B，100步配对实验

## 授权与固定条件

- 最新用户指定 `ssh acp` 的四张 H100；不再使用旧 `train2` 连接。ml2 当前评测不受影响。
- 教师 `Qwen/Qwen3-8B`，学生 `Qwen/Qwen3-1.7B`，均为官方指令版，名称没有 Instruct 后缀。
  沿用 2026-09-21 固定的 ModelScope revision、每文件 SHA256，不用 Base、用户模型或训练后权重。
- 两臂从同一原始学生独立初始化，Block3 Mean 训练和完整评测结束后，才开始 Token OPD。
- 每臂100步，32题位置 x 每题1条，PPO minibatch32，seed21，每25步保存完整状态，共25/50/75/100。
  正式训练不从 probe 接续，不删除任何 checkpoint。原始学生已评过，本轮不重复评测。
- 采样沿用当前100步配置的 legacy request seed21，不是旧指令版4x8实验的逐请求派生seed。
  这一点与更改batch、步数、硬件一起记录，不能把新旧实验视为纯算法对照。
- prompt 复用已成功的指令版：原生 Qwen chat，题目后附逐步求解及 boxed 指令，显式
  `enable_thinking=False`。保留模板自带的已闭合空 think 块；训练与评测 token 输入一致。
- EOS151645，显式 stop IDs [151645,151643]，按真实生成长度构造 mask。
- 其余保持历史 lr2e-6、16K响应、actor microbatch1、ref microbatch1、rollout logprob microbatch4、
  vLLM占比0.6、PPO单epoch。保留历史 Block3 联合 ratio 和 block reduction，不是纯 advantage 消融。
- ACP cgroup 配额32CPU，Ray声明32，而不是照搬ml2的64；不改变batch或梯度累积。

## 持久化与停止边界

- 唯一持久根目录 `/mnt/afs/202609/tyf-qwen-opd/`：models、data、deployments、envs、runs、日志、权重、rollout均在AFS。
- `/dev/shm/a17` 只存可重建的编译和Ray缓存，不存实验唯一副本；不把新产物只放 `/workspace`。
- 服务端 nohup + 独立session，SSH断开不停止任务。ACP平台重建/超时仍会停止进程，不能承诺无限存活。
- 不停止或发送信号给 sshd；失败清理只针对控制器自己创建的训练/评测进程组。
- 平台重建后先核对新指纹、主机及AFS完整状态，再建立恢复控制器；不自动从初始模型覆盖重跑。
- 本地1231代理仅关系到SSH连接。连接失败不是任务已停止的证据。

## 实现与验收

- 控制器 `scripts/run_acp_qwen17_n1.py`：复用既有launcher、历史损失、100步sampler审计、完整状态审计、
  指令版prompt验收和完整评测。仅新增AFS/机器适配、32x1配置、检查与编排。
- 每方法独立执行保存Step1、退出、恢复到Step2的GPU门禁；probe也保持100步scheduler horizon。
- 启动前检查固定ModelScope文件、DAPO及四评测集hash、历史graderhash、原始教师资格证据、实际训练collector输入。
- 在ACP真实GPU上分别检查师生非thinking生成，再进入恢复门禁及正式训练。
- 每步归档全部32条原始训练轨迹；Step1及每5步保留全部旧过程诊断和位置快照，训练后生成热力图。
- 每臂3200条轨迹按冻结sampler逐步检查，再核对两臂的题目/顺序/prompt/采样设置一致。
- 每权重按100/75/50/25依次完整评测 MATH500(500)、AIME24(30)、AIME25(30)、AMC23(83)，每题8次。
  使用同一历史grader，保存全部eval rollout，分别报告Avg@8、Pass@8、格式错误、截断；不合并四个benchmark计分。
- 任一子任务、输入检查、恢复检查或评测验收失败即停止队列，保留现场，不自动重试或调参。
- 基础镜像的NGC Torch不是ml2同版ABI，使用独立AFS虚拟环境安装torch2.8.0/vLLM0.11.0等固定版本。
  环境冻结与历史grader依赖差异需记录并实测，不能只凭同一grader脚本宣称完全一致。
