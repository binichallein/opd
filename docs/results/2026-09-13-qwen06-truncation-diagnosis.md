# 0.6B 高截断率：同题诊断与提示格式消融

## 结论

2026-09-13 按用户要求停止完整评测，随后仅在 ml2 完成 192 条诊断推理，
没有更新任何模型权重。直接观察到的失败包括句子、公式和无关词语循环，
不是所有触顶回答都需要更长的有效推理。

提示格式是已观察到的贡献因素；当前聊天包装和强制 `<think>` 指令与
Base 模型之间的适配值得优先排查。相同训练题上，1.7B 经过 Token OPD
Step50 后的截断改善大于 0.6B。但这没有证明“0.6B 天生更容易截断”，
也没有证明所有训练阶段的截断都由同一个机制产生。

没有观察到漏停 `<|im_end|>` 的证据，也没有发现足以解释差异的固定 Token
loss 代码变更。不能把增加停止 token、放宽 16K 上限或改变 block size
直接当作已验证修复。

## 实验一：同一批 32 道训练题

使用原训练 sampler、seed21 的前 8 个 batch，每批 4 题。复用原始环境
MATH_TEMPLATE 和聊天模板，题目及 prompt token IDs 在师生规模间一致；
重建的 Step1/5 prompt 多重集哈希与两次训练记录均匹配。

每个模型每题生成一次：temperature=1、top_p=0.9、top_k=-1、seed21、
max_tokens=16384，EOS=151643，ignore_eos=False。

| 模型状态 | 真正因长度停止 | 比例 | 平均长度/token | 触顶且周期重复 | 历史 grader 判对 |
|---|---:|---:|---:|---:|---:|
| 0.6B Base | 12/32 | 37.50% | 6869.19 | 10/12 | 0/32 |
| 0.6B Token Step50 | 10/32 | 31.25% | 6169.78 | 4/10 | 1/32 |
| 1.7B Base | 16/32 | 50.00% | 8805.84 | 9/16 | 1/32 |
| 1.7B Token Step50 | 4/32 | 12.50% | 4126.00 | 0/4 | 4/32 |

这里“真正因长度停止”使用原始 `finish_reason=length`，不是只看长度。
Base 阶段 1.7B 反而触顶更多；因此不能把模型规模本身当作充分解释。
Step50 后 1.7B 的改善更明显，支持研究不同学生的初始化及学习适配差异，
不能仅凭这一组轨迹证明教师局部反馈、容量或优化中的某个因素是唯一原因。

周期重复使用最后 2048 token 的启发式：至少 256 token，周期 1-128，
至少四个周期，偏移匹配率 >=99%。它不覆盖所有语义重复。
0.6B Step50 剩余六条非严格周期触顶输出中，也能看到重启推导、反复改写
同一表达式、无止境枚举等现象；不把未命中检测器视为正常推理。

## 实验二：同一前 16 题的提示格式消融

只测试两个 Base，权重、采样参数、长度和停止配置不变。

- 原提示：聊天模板 + 逐步推理 + 强制 `<think>...</think>` + boxed 答案。
- no_think：只删去 `conduct reasoning inside <think> and </think> and `
  这段文字；仍保留聊天模板、逐步推理、boxed 答案要求。
- plain：裸题目加 `Solution:`，同时移除聊天包装和环境指令。
  它是组合干预，不能单独归因于聊天特殊 token。

| 模型 | 提示 | 因长度停止 | 比例 | 平均长度/token | 历史 grader 判对 |
|---|---|---:|---:|---:|---:|
| 0.6B Base | 原提示 | 6/16 | 37.50% | 6582.31 | 0/16 |
| 0.6B Base | no_think | 5/16 | 31.25% | 5475.50 | 1/16 |
| 0.6B Base | plain | 1/16 | 6.25% | 1586.50 | 1/16 |
| 1.7B Base | 原提示 | 6/16 | 37.50% | 7081.88 | 1/16 |
| 1.7B Base | no_think | 1/16 | 6.25% | 2439.75 | 1/16 |
| 1.7B Base | plain | 0/16 | 0.00% | 587.56 | 0/16 |

两种消融新增 64 条输出；原提示行是实验一相同前 16 题的子集，不是额外
生成，也不能拿这个 16 题比例直接与实验一 32 题比例比较。

提示格式变化确实降低了这批题上的触顶，特别是 plain 条件。但 0.6B plain
仅 1/16 正确，1.7B plain 为 0/16；不能声称已经找到有效的数学训练修复。
只删除强制 think 要求对 0.6B 的变化仅为 6/16 到 5/16，也不足以将全部
问题归因于这一个指令。

## 停止协议检查

全部 192 条响应 token IDs 均未包含 151645 (`<|im_end|>`)。
所有因长度停止的输出也没有提前出现 EOS151643。因此，增加151645为
停止 token 不会改变已观察到的这些生成路径。这个结论仅限当前样本，
不推广为所有 prompt、checkpoint、随机种子都不存在停止协议问题。

## 解释与下一步建议

目前最有证据的解释是：Base 初始化在现有数学指令格式下会产生退化续写，
其中部分轨迹进入重复循环；0.6B 在相同 Token OPD 步数后仍保留较多这类
失败，而 1.7B 缓解更明显。这是“观察 + 受控提示干预”的解释，不是根因
完全闭环：尚未干预初始化方式，也未测教师在失败前缀上的恢复能力。

建议下一步先用小规模、有对照的初始化实验区分“Base 对格式不适配”与
“0.6B 本身的推理能力不足”：在同一官方 0.6B Base 上比较直接 OPD 与
短教师 SFT 后 OPD，同时报告正确率、长度、重复率及训练成本。SFT 组多出
的训练预算必须单列，不能把增益全部算给 OPD。该建议尚未执行。

确认初始化和停止协议后，再从相同起点做 Token 与 Block3 对照；不得只
给 Block3 更换提示、初始化、EOS 或长度上限。正式 benchmark 仍按用户
要求逐项单独计分，本文训练题诊断不替代完整评测。
