Post-hoc mechanism diagnosis

Block10 OPD 为什么会崩塌？

对 sampled block reverse-KL 的实现、200-step 训练日志和四组对照结果进行联合诊断。结论针对当前单 seed run，区分直接证据、机制解释和仍待排除的混杂因素。

Student：Qwen3-1.7B-Base Teacher：Qwen3-4B-Base-GRPO Data：DAPO-Math-17K Seed：21 Checkpoint：step 200 诊断状态：机制高度可疑，因果尚需同机复现

结论先行

block10 不是因为梯度消失，也不是被某一次未受控的数值爆炸直接击穿。 最符合代码与时间序列的解释是：10-token 共享 advantage 引入大量跨 token 信用项，使更新方向长期高方差；学生开始偏离后，teacher 在 OOD 前缀上的 sampled-token 负反馈继续污染整个 block，最终形成高熵、超长、全格式错误的自强化崩塌。

1. 从 token OPD 到 block10，梯度结构发生了什么变化

实现并不是简单地把 10 个 token 的 loss 做平均。它同时把 10 个 token 的旧策略与当前策略 log-prob 相加，形成一个 block action；随后用同一个 block advantage 更新整个片段。

Token-level sampled OPD
At = log πT(yt | ht) − log πold(yt | ht)
Ltoken ∝ − Σt At · rt
每个 token 主要使用自己的 teacher-vs-student 信号：错误 token 被压低，合理 token 可以保留自己的正向或弱负向信用。
当前 block10 mean 实现
ĀB = (1 / k) Σt∈B At
log rB = Σt∈B [log πθ(yt) − log πold(yt)]
一个 token 的强负信号会进入 block 均值，并通过同一个 ĀB 作用到另外 9 个 token。

关键展开：自身信用之外，多出了交叉信用

∇LB ∝ − ĀB Σs∈B ∇logπθ(ys)
∝ − Σt At ∇logπ(yt) − Σt≠s At ∇logπ(ys)
token 自身项：与 token OPD 的信用方向一致 交叉项：其他 token 的 advantage 改写当前 token

上式省略了不影响这里结论的公共归一化系数。重要的是交叉项数量随 k 二次增长，而不是简单线性增长。

为什么 mean 没能解决问题？

advantage 除以 k 控制了标量幅度，却没有删除交叉项。与此同时，loss 从 T 个 token 单元变成约 T/k 个 block 单元，外层平均会抵消一部分缩放。因此 mean 能缓解 naive sum 的直接放大，却不能消除共享信用带来的方向污染。

3. 为什么 sampled-token 反馈会把漂移变成恶性循环

本轮使用的是学生已采样 token 上的 teacher log-prob 差值，不是 full/top-k teacher distribution。它擅长表达“当前 token 不应这么高”，但不会直接给出“应该换成哪个 token”。

01
跨 token 信用泄漏
一个强负 At 同时影响 block 内其余 9 个 token。
02
正常 token 被一起压低
推理连接词、数学符号、格式与 EOS 都可能继承错误信用。
03
概率质量扩散
只有采样 token 被评价，质量转移到未被 teacher 明确指导的词表区域。
04
学生 prefix 进入 OOD
高熵采样产生随机多语种片段，teacher 的局部评分可靠性下降。
05
负信号进一步加重
未裁剪 log-ratio 在异常 prefix 上产生更负、更偏斜的 advantage。
06
超长随机 rollout
reward 已为 0，但纯 OPD 仍继续更新，循环没有自动刹车。
配置中的三个放大条件
  • clip_log_ratio=False：token advantage 未裁剪，观察到最负约 −20.8。
  • reward_weight=0：outcome reward 归零不会停止或反转 OPD 更新。
  • full/top-k KL 未启用：teacher 不为未采样替代 token 提供密集正向方向。
为什么高熵不违背 reverse KL 的理论？

精确 reverse KL 的最优解不会是随机碎片；这里失败的是 sampled、block-shared 的梯度估计器及其 OOD 反馈条件。大量负信用广播只是在压低当前样本，并不等于精确追随 teacher 的完整分布。

4. 梯度裁剪阻止数值爆炸，却修复不了错误方向

5. 证据强度：哪些已经确认，哪些仍是解释

直接观察

高置信事实

  • block10 在 step 50–60 出现熵和长度快速上升。
  • 200/200 step 的裁剪前 grad norm 均大于 1.0。
  • 没有 NaN/Inf，也没有梯度消失。
  • step-200 的 5,144 条 eval rollout 全部格式错误。
代码 + 动力学支持

最可能机制

  • block advantage 广播产生 90 个跨 token 信用项。
  • 未裁剪的负 advantage 污染同 block 的正常 token。
  • sampled-only 反馈与 OOD prefix 构成自强化漂移。
  • 持续全局裁剪限制大小，但保留噪声方向。
次要假设

可能的放大因素

  • 10-token 联合 likelihood ratio 的乘法方差。
  • 固定 block 边界跨越语义步骤和答案格式边界。
  • 长回复让更多 OOD 状态进入后续更新。
尚未排除

因果混杂

  • block10 在 4×A100 上运行，其他三组在 4×A800 上运行。
  • 驱动与 Python patch 版本不同。
  • 目前只有 seed=21，没有同机重复实验。
  • 未记录逐 block advantage 符号率和相邻梯度 cosine。
因此当前可以写：“这次 block10 run 的崩塌与实现中的跨 token 信用、sampled-only OOD 反馈和持续梯度裁剪一致。” 不能写成：“已经证明所有 k=10 block OPD 都必然崩塌。”

6. 最小验证实验：如何真正确认根因

下一轮不需要立刻再跑完整 200-step × full eval。先在同一台 A800 机器、相同 seed/data 上运行到 step 70，观察哪个干预能阻止 entropy 在 step 50–60 上升。

A. 原始 block10

同机复现当前设置，确认崩塌不是 A100/驱动造成的偶然分叉。

B. 去交叉信用对照

保留 10-token 数据组织，但每个 token 使用自身 At，直接检验共享信用是否为主因。

C. Advantage clip

只把 token log-ratio 裁到 [−5, 5]，判断极端负信号是否驱动 OOD 循环。

D. Outcome / overlap gate

错误轨迹或低 teacher-student overlap block 不更新，测试 teacher-on-OOD-prefix 失真。

必须新增的诊断指标

  • 每个 block 的 advantage 正/负比例、均值、标准差与最小值。
  • 实际 gradient clip coefficient，而不只记录裁剪前 norm。
  • 相邻 step 梯度 cosine，区分“范数大”与“方向来回震荡”。
  • teacher/student top-k overlap 随 prefix 深度的变化。
  • EOS、数学符号、格式 token 在 block 中收到的共享 advantage。
可证伪标准：如果同机原始 block10 不再崩塌，硬件/随机路径解释上升；如果只有“去交叉信用”组稳定，credit leakage 得到强因果支持；如果仅 advantage clip 或 OOD gate 稳定，则极端负信号或 teacher prefix 可靠性是更直接的控制点。
