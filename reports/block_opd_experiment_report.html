Block Reverse-KL OPD：从单 token 到连续 token block 的验证

目标：验证“teacher 同时给学生连续 2/3 个 token 的采样路径打分，再用 block 级 reverse-KL 风格信号更新学生”是否比标准 token-level OPD 更有效或更稳定。

实验机：train Student：官方 Qwen3-0.6B Teacher：官方 Qwen3-4B 完整 eval：GSM8K 1319 + MATH500 500 Run：block_opd_effect_20260708_124329

Idea 定义

现有 OPD 通常是逐 token 监督：学生生成一个 token，teacher 就评价这个 token 比旧学生更应该被鼓励还是压低。你的想法是把连续几个 token 合成一个小片段，让 teacher 评价整个片段。

标准 token OPD：如果学生生成 y1, y2, y3, y4，就分别评价 y1、y2、y3、y4 四个 token。
block-2 OPD：把它们切成 [y1, y2] 和 [y3, y4] 两个连续 block，teacher 一次评价一个 block。
teacher 对 block 的分数：log p_teacher(y1) + log p_teacher(y2 | y1)。这就是 teacher 认为连续片段 [y1, y2] 有多合理。
旧学生对同一 block 的分数：log p_old(y1) + log p_old(y2 | y1)。
两者相减：teacher_block_score - old_block_score。如果为正，说明 teacher 比旧学生更喜欢这个连续片段；如果为负，就说明 teacher 更不喜欢。
训练目标：teacher 更喜欢的 block，就提高当前学生生成这个 block 的概率；teacher 不喜欢的 block，就压低它的概率。
这里验证的是 sampled block reverse-KL：只评价学生已经生成出来的连续 token block，例如 [y1, y2]，不枚举所有可能的 2-token 或 3-token 组合。

实验结论

部分成立。 block-3 在 GSM8K 和 MATH500 上都略高于 token OPD，说明 block-level 信号不是无效方向。

但稳定性不干净。 block-2 和 block-3 的 pre-clip grad norm 明显更高，block-3 的 max grad norm 达到 1136。

下一步更合理的研究问题不是“block 越大越好”，而是“block advantage 是否需要按长度归一化、温度缩放或裁剪”。

数学公式：token 监督 vs block 监督

下面用可视化公式展示两者的差别。蓝色项是标准逐 token OPD 已经有的部分；橙色项是 block-level 额外引入的交叉项。

1. Token-level OPD：每个 token 各用各的信号
At = log πT(yt | x, y<t) − log πold(yt | x, y<t)
Ltoken = − Σt sg(At) · log πθ(yt | x, y<t)
直觉：第 t 个 token 的 teacher 信号，只更新第 t 个 token 的概率。
2. Block-level OPD：连续 token 共享一个整体信号
Bj = (ys, ys+1, ..., ys+k−1)
AB = Σi=0k−1 [log πT(ys+i | x, y<s+i) − log πold(ys+i | x, y<s+i)]
Lblock = − Σj sg(ABj) · log πθ(Bj)
直觉：teacher 不是单独评价每个 token，而是评价整个连续片段。
3. block-2 展开：为什么它不是普通逐 token OPD

设一个 block 是 [y1, y2]，并定义两个 token 的 advantage：

A1 = log πT(y1) − log πold(y1)
A2 = log πT(y2 | y1) − log πold(y2 | y1)
逐 token loss
Ltoken = − A1 log πθ(y1)
− A2 log πθ(y2 | y1)
block-2 loss
Lblock-2 = − (A1 + A2) · [log πθ(y1) + log πθ(y2 | y1)]
Lblock-2 = − A1 log πθ(y1) − A2 log πθ(y2 | y1) − A1 log πθ(y2 | y1) − A2 log πθ(y1)
核心差别：逐 token OPD 只有蓝色项；block-2 OPD 多了橙色交叉项。也就是说，block 内 token 共享一个整体 teacher 信号，所以它更像“短语/推理片段级监督”，但也会放大梯度并让 credit assignment 变粗。

下一轮实验：控制 block advantage 的尺度和归因泄漏

上一轮 naive block aggregation 说明 block-3 有轻微收益，但梯度范数明显放大。下一轮不再只问“block 是否有效”，而是验证：能否保留 block 片段级信号，同时降低梯度放大和 credit assignment leakage。

实验 A：naive block-3（已有对照）
AB = A1 + A2 + A3
L = − sg(AB) · [logp1 + logp2 + logp3]
作用：保留当前 block-3 的片段级监督；风险是 advantage 求和会放大梯度。
实验 B：mean block-3
AB = (A1 + A2 + A3) / 3
L = − sg(AB) · [logp1 + logp2 + logp3]
目标：验证简单长度归一化能否降低 grad norm，同时尽量不损失 block-3 的性能。
实验 C：mixed block-3
Amix,i = (1 − λ) Ai + λ mean(A1, A2, A3)
L = − Σi=13 sg(Amix,i) · logpi
目标：保留 token 自己的 credit assignment，同时加入 block 的整体趋势。本轮设 λ=0.5。
判定标准

如果 mean 或 mixed 在 GSM8K/MATH500 接近或超过 naive block-3，同时 grad norm 显著低于 naive block-3，就说明真正有价值的方向是 variance-controlled / credit-preserving block OPD，而不是简单的固定 k 聚合。

实验配置沿用上一轮：官方 Qwen3-0.6B student、官方 Qwen3-4B teacher、50 steps、完整 GSM8K + MATH500 eval、完整 regrade。

结论：你的“给 token advantage 做权重”的方向有实验证据支持。最简单的等权归一化 sum / k 已经把 naive block 的梯度放大压下来，并且在两个 eval 上都略优于 naive block-3。
但结论不是“越 block 越好”。当前更准确的 idea 是：block-level reverse-KL 需要 variance-controlled advantage aggregation。下一步应做 sum / sqrt(k)、advantage clipping、以及 λ ∈ {0.2, 0.8} 的 mixed sweep。

论文级 Baseline 设计

当前实验主要是内部 ablation：token OPD、naive block、mean block、mixed block 都在同一 trainer、同一官方 student/teacher、同一数据和 seed 下比较。这可以证明 block objective 内部哪个设计更合理，但如果要写论文，还需要和社区认可的方法对齐。

Baseline 作用 与本 idea 的关系 优先级
Base model 官方 Qwen3-0.6B 不训练 证明后训练本身带来增益 必须
SFT / off-policy KD teacher 生成解答，student 做监督微调 证明 on-policy/block OPD 不是被简单 SFT 打败 必须
Standard sampled-token OPD 每个位置只用 student 实际采样 token 的 log-ratio 监督 这是本方法直接改造的对象；可按 GKD / MiniLLM / Rethinking OPD 的定义实现 必须
Student-TopK OPD 在 student top-k token 上做 OPD，而不是只看 sampled token 回答“同一 prefix 上看更多 vocab token 是否更好”；与我们的“沿时间看多个 token”互补 必须
Teacher-TopK / Local Support Matching 在 teacher 支持集上做 truncated reverse-KL，并配合 top-p rollout / special-token masking 来自 Revisiting OPD，是当前很强的稳定性 baseline 强烈建议
FiRe-OPD trajectory-level filter + token-level soft reweighting 和我们同属“重新分配 OPD supervision granularity / weight”的路线 建议
TOPD 用 near-future trajectory 判断真实分叉，并把 guidance 分配到未来多个 token 动机非常接近：都认为 isolated token-level correction 不够 建议
Blockwise Policy-Drift Gating 把 old-current student logprob shift 按 block 聚合，mean-normalized 后作为 loss gate 名字和机制都最接近“block + weight”，但它不改 teacher block logprob，只做 blockwise reweighting 相关工作必须讨论
推荐论文表述：不要写“我们只和自己的变体比较”。更合适的是：We compare against standard sampled-token OPD and Student-TopK OPD following the OPD formulation and recipe in Li et al. (2026), and include stronger stability/reweighting baselines such as Teacher-TopK/LSM, FiRe-OPD, TOPD, and blockwise policy-drift gating when compute allows.
最小可接受 baseline 组合：Base + SFT/KD + sampled-token OPD + Student-TopK OPD + Teacher-TopK/LSM + naive block + mean block。其中 naive block 是内部 ablation，不是外部方法 baseline。

这次实验说明了什么

支持该 idea 的证据

block-3 在两个任务上都略高于 token OPD：GSM8K 从 0.4594 到 0.4685，MATH500 从 0.200 到 0.202。虽然提升很小，但方向一致。

block supervision unit 明显减少，但性能没有崩，说明连续 token 的联合 logprob 信号可以承载有效监督。

反对或需要修正的证据

block-2 在两个任务上都略低于 token OPD，说明 block 化不是单调收益。

block-2/3 的 grad norm 明显放大，说明简单求和会改变 loss 尺度，可能需要按 block length 归一化、温度缩放或 advantage clipping。

当前最合理结论：这个方向值得继续，但下一轮应测试 sum / k、sum / sqrt(k)、block advantage clipping，以及与原 token OPD 的 mixed objective。
